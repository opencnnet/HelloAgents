# 提示词：AI 聊天前端（Vue 3 + Vite + TypeScript，Web / Tauri 双端）

> 使用方式：整段复制给编码助手，在空目录下执行。
> 本提示词只约定**做什么**和**用什么技术**，不约定具体界面代码与样式实现；界面以 `prototypes/ai-chat-ui.html`（已评审通过的静态原型）为视觉基准，实现时对齐该原型的观感即可。

---

## 1. 项目目标

实现一套 AI 聊天前端，同一份代码同时产出两种形态：

1. **Web 静态站点**：构建产物可直接部署到任意静态托管。
2. **Tauri 2.0 桌面客户端**：Rust 外壳 + 系统 WebView，覆盖 Windows / macOS / Linux。

**核心架构约束**：业务代码不得直接触碰 `fetch`、`localStorage` 或 Tauri API，必须经由适配层；适配层在运行时自动识别 Tauri / 浏览器环境并切换实现。

---

## 2. 技术栈

| 类别 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3.5（组合式 API + TypeScript） | 单页应用，不引入路由 |
| 构建 | Vite 6 | 相对路径 base，便于静态托管与 Tauri 加载 |
| 状态管理 | Pinia | 设置、会话、连接状态三个 store |
| Markdown | markdown-it + highlight.js | 支持代码高亮 |
| 安全 | DOMPurify | 渲染 AI 返回内容前必须净化 |
| ID 生成 | nanoid 或原生 `crypto.randomUUID` | |
| 桌面端 | `@tauri-apps/api@2`、`@tauri-apps/plugin-store@2`、`@tauri-apps/cli@2`（开发依赖） | |
| 工程化 | TypeScript 5.6+、vue-tsc、ESLint、`@types/node` | 构建前执行类型检查 |
| 后端（Rust 侧） | reqwest（流式转发）、tokio、serde | 仅 Tauri 端需要 |

**明确排除**：任何 UI 组件库（Element Plus / Ant Design Vue / Naive UI 等）、Tailwind、jQuery。样式手写，使用 CSS 变量统一管理主题，支持明暗切换。

## 4. 功能需求

### 4.1 多轮会话管理
- 新建会话、切换会话、重命名、删除（删除需二次确认）。
- 会话列表按时间分组展示（最近 / 更早），展示标题与更新时间。
- 新会话的首轮对话结束后，自动用 AI 首条回复摘要生成标题。
- 提供「清空本地数据」，二次确认后清空会话与设置并回到未配置状态。

### 4.2 消息与输入
- 消息气泡列表，区分用户与 AI；支持时间戳、复制、重新生成。
- 输入框：Enter 发送、Shift+Enter 换行、内容为空时禁用发送、**生成中整体禁用**。
- 生成中提供「停止」操作；支持滚动到底部与「回到最新」。

### 4.3 AI 流式回复
- 基于 SSE 增量接收，逐字渲染；未收到首包前展示等待状态。
- 支持中止（保留已生成内容，不丢弃）。
- 支持重试（保留用户消息，仅重建 AI 占位消息，避免重复发送）。

### 4.4 内容展示
- Markdown 渲染：标题、列表、引用、表格、行内代码、链接。
- 代码块：语言标签、一键复制、语法高亮。
- 渲染前统一做 HTML 净化，防范 XSS。

### 4.5 加载与错误
- 状态覆盖：等待首包、流式生成中、已完成、失败。
- 失败时展示错误摘要与原因，提供重试入口。
- 错误分类：网络、鉴权、限流、服务端、用户中止、解析失败，分别映射为中文提示。

### 4.6 本地持久化
- 会话、消息、设置全部本地保存；刷新后完整恢复。
- 消息状态变化后防抖落盘；会话列表变更立即落盘。

### 4.7 配置管理（UI 内配置，重点）
- 在设置弹窗中配置：**接口地址、API Key、接口类型、模型名称、Temperature、Top P、最大输出 Tokens、上下文轮数、系统提示词、流式输出开关**。
- 模型服务类型支持 **OpenAI 兼容、本地模型及 Anthropic Messages**；自定义地址通过 OpenAI 兼容类型填写。模型列表可通过服务端模型列表接口获取，也允许手动输入。
- 提供「测试连接」，结果就地反馈（成功显示延迟，失败显示状态码与原因）。
- 提供「恢复默认」。
- 保存后立即重新检测连通性并刷新连接状态。

## 5. 界面规范（描述性约定）

整体为「侧边栏 + 主区」两栏结构，主区自上而下为：顶栏、消息区、输入区、底部状态栏。具体视觉、配色、间距对齐静态原型实现。

- **顶栏**：仅承载当前会话上下文（标题、消息数、时间），**不显示模型信息，不放设置按钮**，右侧留白。
- **侧边栏**：会话列表与操作区，**设置入口唯一放在侧边栏底部**，未配置时该入口带「待配置」标记。
- **消息区**：用户消息与 AI 消息左右区分；AI 消息支持 Markdown 与代码块；流式生成时尾随光标，生成中提供停止，失败时展示可重试的错误卡片。
- **输入区**：随内容增高，达到上限后内部滚动；底部提示键位与字数；未配置接口时禁用并说明原因。
- **底部状态栏**：**全局唯一的连接状态展示位**。
  - 未配置：展示「未连接 · 未配置接口与模型」，**整条可点击并直达设置**。
  - 已连接：展示主机与模型，此时不可点击。
  - 其余状态：连接中、请求失败，分别用状态点与文案区分。
  - 右侧展示当前运行环境（Web 或桌面端）与本地保存提示。
- **响应式**：窄屏下侧边栏改为抽屉（带遮罩），隐藏次要信息；适配移动端安全区。
- **主题**：明暗双主题，默认浅色，颜色统一走 CSS 变量。

## 6. 适配层设计

### 6.1 环境探测
提供运行时判断（检测 Tauri 内部全局对象是否存在），导出运行时类型与平台信息，供其余模块读取。

### 6.2 存储适配器
- 统一异步接口：`读取 / 写入 / 删除`（泛型，内部负责序列化）。
- Web 实现：浏览器本地存储，需处理配额超限异常。
- Tauri 实现：官方 Store 插件，加载后使用、写入后落盘。
- 统一键名前缀，会话与设置使用不同键。

### 6.3 请求适配器
- 统一接口：`流式对话`，入参为消息数组 + 模型参数 + 回调集合 + 中止信号；回调包含开始、增量片段、完成、错误四类。
- Web 实现：`fetch` 发起请求并以流方式读取响应体，按 SSE 帧边界解析，忽略注释帧与结束标记，拼接增量文本。
- Tauri 实现：优先调用 Rust 命令，由 Rust 侧发起 HTTP 请求并通过事件向前端推送增量、完成、错误。**理由**：绕开 WebView 的 CSP 与跨域限制，密钥可留在 Rust 侧。
- SSE 帧解析抽成与传输方式无关的纯函数，便于单测。
- 统一错误模型，携带错误类别、可读文案与可选状态码。
- 支持中止信号，对应界面上的「停止」。

### 6.4 配置优先级
UI 内配置 > 环境变量 / 内置配置文件默认值 > 代码内置兜底值。
首次启动无配置时进入「未配置」状态：**必须正常渲染界面**，不白屏、不抛异常。

## 7. 数据模型

- **消息**：ID、角色（用户 / AI / 系统）、内容、创建时间、状态（等待中 / 生成中 / 完成 / 失败）、错误信息、用量统计。
- **会话**：ID、标题、创建时间、更新时间、消息数组、创建时使用的模型快照。
- **设置**：接口地址、密钥、接口类型（OpenAI 兼容 / Anthropic Messages / 本地模型）、模型名称、Temperature、Top P、最大输出 Tokens、上下文轮数、系统提示词、是否流式。
- **连接状态**：未配置、未检测、检测中、已连接（含主机与模型）、错误（含文案）。

---

## 8. 关键实现要求

1. **流式性能**：增量内容做节流后再触发 Markdown 重渲染，避免逐 token 全量解析。
2. **XSS 防护**：Markdown 渲染结果必须净化后再插入 DOM；禁用原始 HTML 解析。
3. **滚动体验**：仅在用户处于底部附近时自动滚动，用户上滑时暂停自动滚动。
4. **中止语义**：停止后已生成内容保留并标记为完成。
5. **密钥安全**：密钥只存本地，不写入仓库、不写进内置配置文件，日志中脱敏。
6. **上下文裁剪**：按上下文轮数截取历史消息后再发起请求。
7. **可测试性**：SSE 解析、存储序列化、配置合并逻辑与 UI 解耦，便于单测。

## 9. 构建与运行

**脚本约定**：开发、类型检查 + 构建、本地预览、桌面端开发、桌面端构建、桌面端打包五类入口。

**Vite 关键配置**：
- 相对路径 base，保证静态托管与 Tauri 加载都能工作。
- 固定开发端口并启用热更新；环境变量前缀同时放行 `VITE_` 与 `TAURI_`。
- 构建目标面向现代浏览器；调试构建开启源码映射。

**Tauri 关键配置**：
- 开发命令与构建命令分别指向上述脚本，前端产物目录指向构建输出。
- 开发地址指向 Vite 开发服务器端口。
- 窗口默认尺寸与最小尺寸合理设置，标题自定义。
- 按需声明能力（存储插件、网络访问、窗口控制）。

**运行说明（写入 README）**：

```bash
# Web
pnpm install
pnpm dev      # 本地开发
pnpm build    # 产物可直接静态部署

# 桌面端（首次需安装 Rust 工具链与 Tauri 系统依赖）
pnpm tauri dev     # 桌面端热更新开发
pnpm tauri build   # 产出安装包，位于 src-tauri/target/release/bundle/
```

## 10. 验收标准

- [ ] 未配置时界面正常渲染：底部状态栏提示未连接且可点击直达设置，输入区禁用，无任何报错
- [ ] 配置保存并测试通过后：状态栏显示主机与模型且不可点击，输入区恢复可用
- [ ] 新建 / 切换 / 重命名 / 删除会话正常，刷新后完整恢复
- [ ] Enter 发送、Shift+Enter 换行；生成中输入区禁用，停止后保留已生成内容
- [ ] AI 回复逐字渲染，结束后光标消失；代码块高亮且可复制
- [ ] 断网或密钥错误时展示错误提示，重试可恢复且不重复发送消息
- [ ] 窄屏下侧边栏变为抽屉，布局无横向滚动
- [ ] 类型检查通过，Web 与桌面端两种构建均成功产出
- [ ] 全量搜索确认：组件与 store 中无 `fetch`、`localStorage`、`@tauri-apps` 直接引用

## 11. 约束与禁止事项

- `ai-chat/` 是独立前端子项目，不导入 Python 模块；与 HelloAgents 的集成通过 HTTP SSE 契约完成。
- 仅 `src/adapters/` 允许直接访问网络、本地存储与桌面端 API，其余目录一律经由适配层。
- 密钥不入库、不写内置配置文件、不打印明文。
- 不引入 UI 组件库、Tailwind、jQuery 等未列依赖。
- 不新增未经确认的入口或状态展示位：设置入口仅侧边栏底部一处，连接状态仅底部状态栏一处，顶栏不显示任何模型或连接信息。
- 未配置接口时不得阻塞渲染或抛出异常。
